### 2. 修正後的 README 是否符合程式行為

- **「不自動促升」**：`isPromotable` 對 dismissed 回 false（E6），sync 與 submit 的自動促升都要經過這道閘門。描述正確。
- **「之後 `--submit` 仍可讓它進 recall」**：`submitAgentSummary` 不檢查原本的狀態，一律改成 enriched，再依一般規則判斷是否促升（E7）。
  - merge 與 release 會直接通過；低重要度又沒有內容的 commit_range 不會促升。
  - README 用的是「可」（can），沒有說「一定會」，所以描述正確，也與 SCN-006「依一般規則促升」一致。第三輪的 E12 探針實測 merge 會促升（`memory_sources` 從 0 變成 1）。
- **「明確的 `--promote` 仍可」**：`promoteEligible(force=true)` 會略過 `isPromotable`（E7）。描述正確。
- **「enriched 或已在 recall 時回 409」**：與 E4、E5 相符，與 `server.ts` 第 27 行的路由註解也一致。
- **批次列「已在 recall 的會跳過（`skipped_promoted`）」**：本輪沒有改動，與 `dismissPendingSummaries` 相符。
